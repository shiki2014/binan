# 数据库主存储架构说明

## 目标

将系统从“文件 + 数据库混合运行”改为“数据库主存储，文件仅作兼容导入与归档备份”。

## 当前主存储分层

- `SQLite / PostgreSQL`
  - 系统配置：`system_settings`
  - 交易参数：`trading_parameters`
  - 监控事件：`monitor_events`
  - 风险事件：`risk_events`
  - 账户快照：`account_snapshots`
  - 持仓快照：`position_snapshots`
  - 审计日志：`operation_audits`
  - 变更审批：`change_requests`
  - 订单流水：`trade_orders`
  - 交易对缓存：`exchange_symbols`
  - 指标缓存：`symbol_indicators`
  - 黑白名单：`symbol_lists`
  - 运行时状态：`runtime_state`
  - 应用日志：`system_logs`
  - 维护任务记录：`maintenance_runs`

## 新的运行时数据映射

- `data.json`
  - 迁移到 `exchange_symbols`
- `ATR.json`
  - 迁移到 `symbol_indicators.atr`
- `volatility.json`
  - 迁移到 `symbol_indicators.volatility`
- `trendOscillation.json`
  - 迁移到 `symbol_indicators.trend_oscillation`
- `blackList.json`
  - 迁移到 `symbol_lists`，`list_type=blacklist`
- `whiteList.json`
  - 迁移到 `symbol_lists`，`list_type=whitelist`
- `equity.json`
  - 迁移到 `runtime_state.key=equity_peak`
- `logs/app.log`、`logs/error.log`
  - 新写入 `system_logs`

## 文件目录安排

- `data/trade_assistant.db`
  - SQLite 主数据库文件（默认）
- `PostgreSQL`
  - 通过 `DB_DIALECT=postgres` + `DATABASE_URL` 或 `PG*` 环境变量启用
- `data/*.json`
  - 只保留为历史兼容导入源，不再作为运行时主读写入口
- `data/archive/legacy-runtime/`
  - 首次维护任务会自动复制归档旧 JSON 与文件日志
- `dist/`
  - 前端构建产物
- `logs/`
  - 仍可保留 log4js 文件输出用于本机排障，但控制台读取来源已经改为数据库

## 迁移与维护机制

- 启动时自动执行 `schema_migrations`
- 若数据库表为空，则自动从历史 JSON 导入一次
- 导入完成后，业务逻辑统一从数据库读取
- 定时维护任务自动执行：
  - 旧文件归档
  - 日志、快照、审计、订单流水按保留期清理
- 旧 JSON 不再参与策略实时决策

## 运行链路说明

- 策略引擎：`services/strategyEngineService.js`
- 调度器：`controllers/timingController.js`
- 下单执行：`services/tradeExecutionService.js`
- 仓位生命周期：`services/positionLifecycleService.js`
- 市场缓存刷新：`services/marketCacheService.js`
- 统一数据库访问：`core/dbClient.js`

## 安全与风控补充

- 关键交易参数与系统开关支持高风险确认头
- 支持 API IP 白名单与基础限流
- 实盘下单前增加 `LIVE_TRADING_CONFIRMED=1` 显式确认
- 执行链路内置：
  - 紧急停机
  - 单笔名义价值上限
  - 日内名义价值上限
  - 最大持仓名义价值上限
