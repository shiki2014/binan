# 数据库化改造执行计划

## 目标

将当前交易系统从“脚本化混合存储”推进为“数据库主存储 + 可迁移主库 + 可审计控制面”。

## 阶段计划

### 第一阶段：统一数据访问层

- 引入统一数据库访问入口 `core/dbClient`
- 新增服务优先走 `dbClient`
- 将旧服务从 `core/database` 迁移到 `dbClient`

当前状态：
- 已完成

### 第二阶段：拆分调度与策略模块

- 将 `timingController` 拆为：
  - `scheduler`
  - `strategyEngine`
  - `executionService`
  - `riskPostProcessor`
- 目标是降低单文件复杂度，便于测试与替换执行链路

当前状态：
- 已完成
- 已拆出并接入：
  - `services/marketCacheService.js`
  - `services/tradeExecutionService.js`
  - `services/positionLifecycleService.js`
  - `services/positionStateService.js`
- `services/strategyEngineService.js`
- `controllers/timingController.js` 已收口为调度入口

### 第三阶段：补正式迁移与清理机制

- 增加 schema migration 机制
- 增加快照、日志、订单流水的清理归档任务
- 明确旧 `data/*.json` 的归档策略

当前状态：
- 已完成
- 已新增：
  - `core/migrationRunner.js`
  - `migrations/001_add_trade_order_notional_and_maintenance_runs.js`
  - `services/dataRetentionService.js`
- 已接入启动流程：
  - 自动迁移
  - 旧文件归档
  - 定时数据清理

### 第四阶段：切换 PostgreSQL 主库

- 在 `dbClient` 中增加 PostgreSQL 方言实现
- 补环境变量和连接配置
- 保留 SQLite 作为本地/单机模式

当前状态：
- 已完成
- 已新增：
  - `core/postgresDatabase.js`
  - `core/dbClient.js` PostgreSQL 适配
- 当前支持：
  - `DB_DIALECT=sqlite` 默认本地运行
  - `DB_DIALECT=postgres` 使用 PostgreSQL 初始化与访问

### 第五阶段：安全收口

- 高风险操作二次确认
- 更清晰的权限边界
- 密钥存储与加载策略收口

当前状态：
- 已完成
- 已新增：
  - `services/securityService.js`
  - API 白名单与基础限流
  - 高风险操作确认头
  - 紧急停机
  - 实盘显式确认
  - 单笔 / 日内 / 最大持仓名义价值限制

## 最终状态

当前系统已经完成从“文件主链路脚本”到“数据库主存储交易系统骨架”的过渡：

- 运行时数据主存储已数据库化
- 调度、策略、执行、风控后处理已拆分
- 迁移与清理机制已落地
- PostgreSQL 已具备接入入口
- 安全与风控已进入执行链路而不是停留在文档
