# 全面改造安全方案（V2）

## 目标

- 保持现有交易能力不中断
- 让图形化管理、数据库主存储、监控与审计形成闭环
- 把安全控制前移到真实执行链路，而不是只停留在文档

## 已落地能力

### 访问安全

- `API_TOKEN` 鉴权
- `API_IP_WHITELIST` IP 白名单
- API 基础限流：
  - `API_RATE_LIMIT_ENABLED`
  - `API_RATE_LIMIT_MAX_REQUESTS`
  - `API_RATE_LIMIT_WINDOW_SECONDS`

### 操作安全

- 高风险操作确认：
  - `REQUIRE_HIGH_RISK_ACK=1`
  - `HIGH_RISK_ACTION_TOKEN`
- 关键系统配置和关键交易参数更新支持确认头
- 变更审批通过/驳回支持高风险确认
- 系统维护任务支持高风险确认

### 交易安全

- 紧急停机：`system_settings.emergency_stop_enabled`
- 实盘显式确认：
  - `TRADING_MODE=live`
  - `LIVE_TRADING_CONFIRMED=1`
- 下单前风险限制：
  - 单笔名义价值上限
  - 日内名义价值上限
  - 最大持仓名义价值上限
- 订单幂等键与唯一约束，防重复下单

### 数据安全

- 运行时数据数据库化
- 应用日志与错误日志入库
- `schema_migrations` 迁移记录
- 定期数据清理任务
- 历史 JSON / 文件日志自动归档到 `data/archive/legacy-runtime/`

## 推荐上线基线

- 必须设置 `API_TOKEN`
- 生产环境建议设置 `ALLOW_LOCAL_API_WITHOUT_TOKEN=0`
- 对外仅暴露 Nginx，Node 仅监听内网端口
- 配置 `API_IP_WHITELIST`
- 配置 `REQUIRE_HIGH_RISK_ACK=1`
- 配置 `HIGH_RISK_ACTION_TOKEN`
- 默认使用 `TRADING_MODE=paper`
- 实盘前再显式设置 `TRADING_MODE=live` 和 `LIVE_TRADING_CONFIRMED=1`

## 回滚策略

- 代码回滚：恢复上一版本代码
- 配置回滚：恢复 `.env`
- 数据回滚：
  - SQLite：备份并恢复 `data/trade_assistant.db`
  - PostgreSQL：按数据库快照恢复
- 交易回滚：
  - 打开 `emergency_stop_enabled`
  - 停止新版本进程
  - 验证 `/api/system/overview` 与关键交易接口

## 仍需持续关注

- API Key 仍由环境变量提供，后续建议接入专门密钥管理
- 当前权限控制仍偏单管理员模型，后续可继续补 RBAC
- 如果后续引入多实例，需要把限流和任务锁改成 Redis / DB 级共享实现
